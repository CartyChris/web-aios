## 1. Version control for apps you built

AI Studio could already rewrite an app you made, and that rewrite was destructive: the
model returned a new document, the store replaced the old one, and a worse result was
gone. Asking a model to improve something is a gamble, and a gamble you cannot walk away
from is not a feature anyone uses twice.

`lib/appversions.ts` is pure and holds three invariants, each with tests and each
confirmed live in the browser:

- **Reverting APPENDS.** Going back to v1 does not delete v2 and v3 — it writes a new
  version whose content is v1's. So un-reverting is just reverting again. Verified: a
  three-version history reverted to the original became four versions, with both
  discarded versions still present.
- **Pruning never drops the first version.** A cap is necessary; the one version you must
  always reach is what you had before any model touched it. A plain `slice(-20)` drops it
  on change 21, silently. Verified: after 30 commits the history capped at 20 and
  `history[0]` was still "First version".
- **An oversized or identical version is refused**, not stored. Verified live: a 684 KB
  commit was refused naming the 586 KB limit, and a byte-identical commit was refused too.

Deleting an app takes its history with it — an orphaned version array is invisible and
holds whole documents, which is how a shared quota fills with unreachable data. Verified:
zero orphaned arrays after removing the probe app.

On top of that, **Upgrade with AI** with seven named intents (polish, add a feature, fix a
bug, accessibility, mobile, faster, simplify). Vague instructions are how a model returns
a reimagined app instead of an improved one, so each intent states what must be preserved,
and the prompt tells the model to return the document **unchanged** rather than
approximate it if it cannot comply.

A truncation guard sits in front of the commit: a model that runs out of tokens mid-rewrite
returns a file that looks fine in a list and is broken when you open it. `looksLikeDocument`
catches an unclosed `</html>` or `</body>` and refuses rather than committing it.

## 2. Agent Swarm: per-agent models, chaining, and a router

Directly from the screenshot and the note.

**The 4,000-token ceiling is now 64,000** (floor 256, default 4,096). The old bound was a
slider limit with nothing behind it and it truncated any agent actually asked to write
something. Agents may also carry their own ceiling, so a one-line classifier and a
summariser can sit in the same panel.

**One model for all, or one each.** An agent that names no model inherits the swarm
default — so "run them all on a DeepSeek model" is the empty case, not a separate flag. An
agent that names its own overrides it. The Run tab shows which: `one model: openai/gpt-5.2`
or `2 models`. Verified live: setting one agent to `deepseek/deepseek-chat` flipped the
chip to "2 models".

**Agents can now trigger each other.** An agent declares what it `dependsOn`, and
`planWaves` turns those declarations into topological waves — everything in a wave runs in
parallel, the next wave starts when the previous finishes, and a dependent agent is shown
its upstreams' output. A roster where nothing depends on anything is one wave, which is
exactly the old behaviour.

Verified live, per formation: Research Desk `1 wave, 4 parallel` (unchanged); Red/Blue
`2 waves (2, then 1)`; Tournament `2 waves (3, then 1)`; Steelman/Teardown `3 waves`;
Pipeline `4 waves`.

Three refusals, because a swarm that starts nothing and says nothing is the worst outcome:
a cycle (named, with members), a dependency on an agent that does not exist, and — the
subtle one — **a dependency on a switched-off agent**. That graph is acyclic and every id
resolves, so a naive planner accepts it and the dependent waits forever for output that
never comes.

**An intelligent router.** A model reads the question and proposes the assignment: which
model each agent runs on, which must wait for which, and how many tokens each needs. It
proposes; it does not decide. `parseRouterPlan` validates every field against what exists —
an invented model is dropped and recorded, a self-dependency is stripped, a token figure is
clamped — and `applyRouterPlan` refuses the whole plan wholesale if it would not run, so a
bad suggestion costs one call and leaves the roster you had intact. Partial application
would leave half a routed swarm, which is the worst of both.

Four new formations that use the chaining: **Pipeline** (research → design → build →
review), **Tournament** (three independent attempts, then a judge that never watched them
being made), **Steelman / Teardown**, and the existing Red/Blue now chains its Challenger
behind both sides.

## 3. Pets: what it says, and how it says it

The old catalogue conflated two questions. Every "personality" also instructed the pet to
give desktop tips, so the voice choice was cosmetic — a gremlin and a scholar said the same
sentence in different costumes.

Split into two axes that multiply:

- A **MODE** is the subject: Friend, Inspiration, Coach, True things, Lore, Still, Gremlin,
  Haiku, Oracle, Hype, Story, Questions, Wordplay, Small talk, Quiet — and Desktop tips, now
  one option among sixteen rather than the only one.
- A **PERSONALITY** is the voice: Deadpan, Feral, Ancient, Scholar, Noir, Bard, Grump,
  Field notes, Ghost, and fifteen more.

16 × 24 = **384 combinations**. A deadpan friend and a feral friend are genuinely different
pets.

Two tests enforce the separation and both caught real violations in my own first draft:
no personality may name a subject, and no mode may name a tone. `hype` was dictating "warm
rather than sarcastic" and had to be rewritten.

Subject is placed **before** voice in the prompt, because a model given the voice first
performs the voice and forgets the assignment — you get a pirate talking about being a
pirate instead of a pirate telling you a true thing about octopuses.

Context is withheld from modes that do not want it: a friend asking how you are does not
need your window list.

**Verified live with no API key**, in Friend mode with a Feral voice: *"You have been at
this a while. Have you had water?"* — and across six clicks, not one desktop tip.

## 4. Themes, and a gate that can fail

16 → 50 palettes. A palette is data, and bad data here is invisible until someone switches
to that theme and finds half the interface unreadable, so `npm run check` gained check 4c:

- muted and body text must clear WCAG AA (4.5:1) on the solid panel they sit on
- accent must clear 3.0:1 as a non-text UI mark
- accent and accent2 must be **perceptually** distinct

That last one needed the right metric. Luminance ratio says a brown and a green of equal
lightness score 1.01 — obviously wrong. Redmean distance respects hue, so it answers the
question actually being asked. The check found three of my own new palettes failing and
they were fixed: `rust` had two oranges, `porcelain` and `citrus` had accents at 2.77 and
2.91 against white.

Confirmed the check fails on a deliberately broken palette before trusting it.

  the UI for all nine formations; the execution loop that runs wave by wave and feeds
  upstream output downstream has not run with real model calls in it.
