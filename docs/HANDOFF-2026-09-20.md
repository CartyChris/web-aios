## 3. What the last seven rounds built

### 3.1 Adaptive icon text (the macOS behaviour)

**Problem Chris reported:** desktop icon labels were unreadable over light wallpaper.

**Fix:** `src/lib/contrast.ts` + `src/shell/useBackdropLuminance.ts` sample the wallpaper into
a luminance grid; `DesktopIcons.tsx` calls `labelStyle(x, y)` to choose `PAPER` (`#ffffff`) or
`INK` (`#050506`) per icon.

**Measured detail worth keeping:** `#0b0b0d` as ink **fails** WCAG AA at the crossover
luminance (ratio 4.44). `#050506` gives 4.52. Pure `#000000` gives 4.59. Do not "tidy" the ink
constant back toward `#0b0b0d`.

**Trap:** `labelStyle` must not read `surfaceRef.current` during render — that trips the React
Compiler `refs` ESLint rule, which is an **error** here, not a warning. It uses `useViewport()`
plus `topInset` instead.

### 3.2 The primary-button contrast bug (19 of 50 themes)

`globals.css` hardcoded `#04121c` text on a gradient accent. On 19 themes that failed AA.
`themes.ts` now emits `--on-accent` / `--on-accent2` computed per theme, and the button uses
`background: var(--accent); color: var(--on-accent)`. `scripts/check.mjs` now asserts it.

### 3.3 The widget creator — root cause and fix

**Chris's report:** "The widget creator IS NOT working at all."

**Root cause:** the old extractor required a *closed* markdown fence. It failed on (a) a prose
preamble before the code, (b) a reply truncated by the 4000-token cap so the closing fence
never arrived, and (c) models that emit a `<think>` block first.

**Fix:** `src/lib/extract-code.ts` handles closed fences (``` or ~~~, 3+ chars), **unclosed**
fences, `<think>` blocks (an unclosed one means no code, correctly), prose preamble via a
`MARKUP_START` regex, and bare JS via `CODE_START`. `explainNoCode(text)` produces a human
error instead of a silent blank.

`WidgetBuilder.tsx` now: `maxTokens: 8000`, `persona: false`, one automatic repair call when
extraction fails, then throws with `explainNoCode`. `IDE.tsx` re-exports the same extractor so
both paths share one implementation.

**Model selection:** `<ModelOverride id="widget" />` sits beside the Build button. Default is
the model selected in the top bar; the override picks a different one for that one generation.
`overrideOpts(v)` returns `{}` unless *both* provider and model are set — that is what makes
"inherit the top bar" the default.

### 3.4 For You — the AI suggests and builds

`src/apps/ForYou.tsx`. `src/kernel/activity.ts` records activity to `webaios.activity.v1`
(cap 300) and `gatherSignals()` merges: VFS files (skipping `/harness/`), user-created apps,
custom widgets, harness objectives, and chat history read from `localStorage["webaios.chat.v1"]`
(user turns only). The model proposes widgets and apps; one click adds a built-in widget,
generates a custom widget via `WIDGET_SYSTEM` + `extractCode`, or opens the app studio with a
seeded prompt. There is an offline fallback list and a rejected-suggestions list.

### 3.5 Pets you can create with a model

`src/lib/petgen.ts` holds `PET_PARTS` as the single runtime source of truth for what the
renderer can draw. `petPrompt()` quotes the user description as JSON data (prompt-injection
hygiene). `parsePetSpec()` validates **every** part against those lists — a model that invents
a part gets rejected rather than rendering a broken pet. `useCustomPets` persists to
`webaios.custompets.v1` (cap 60). `PetMaker()` lives in `Personalize.tsx`.

Pets can also steer the OS-level assistant: `settings.assistantSteering` is `"voice" | "pet"`.

## 5. The environment hazard that will waste your afternoon — SOLVED, do this first

**The repo lives in an iCloud-synced folder, and that is what makes builds hang.** The
previous version of this section blamed dataless `node_modules` stubs and told you to warm
them by reading every file. That treats the symptom, takes ~90 minutes, and does not fix the
real problem. Here is what is actually going on and the one command that ends it.

### The fix — run this once per clone

```bash
xattr -w 'com.apple.fileprovider.ignore#P' 1 node_modules
xattr -w 'com.apple.fileprovider.ignore#P' 1 .next
```

That attribute tells the macOS File Provider to stop syncing those trees. Measured on this
machine, immediately before and after:

| | before | after |
|---|---|---|
| `npm test` (676 tests) | 52 s | **1.2 s** |
| `tsc --noEmit` | hung past 10 min, killed | **2.7 s** |
| `next build` | hung past 20 min, three times | **6.5 s** |

`next build` had never completed on this machine, which is why §4.3 said it was never run.
It was never Next's fault.

### Why it hangs, so you recognise it again

`fileproviderd` mediates every read in a synced folder. With tens of thousands of files in
`node_modules` it saturates, and processes that touch them block in I/O. The signature is
unmistakable and worth memorising:

```bash
ps -Ao pcpu,time,args | grep next-build      # 0.0% CPU, ~3 s CPU time, going nowhere
uptime                                        # load average 40+ with nothing of yours running
ps -Ao pcpu,comm -r | head                    # fileproviderd / bird / cloudd / corespotlightd on top
```

**Zero CPU is the tell.** A slow build burns CPU; a blocked one does not. If a build is
stuck at 0%, stop debugging your change and look at the file provider.

### Two traps

- **Do not `npm ci` inside the synced folder without the xattr set first.** Writing ~28,000
  files kicks off a sync-and-index storm that pushed load average past 47 here and made every
  subsequent build hang. If it happens, set the xattr and wait for `fileproviderd` to settle.
- **If `node_modules` really is evicted** (`ls -lO` shows `compressed,dataless`, `du -sh`
  reports far less than ~540 MB), do not warm it by reading every file. `npm ci` rebuilds it
  from the local `~/.npm` cache — measured at **4 seconds** versus ~90 minutes of rehydration.

Repo files outside `node_modules` can be evicted too, including `public/*.png` and
`next-env.d.ts`. Warming those 78 files is cheap and worth doing:

```bash
find . -path ./node_modules -prune -o -type f -flags +dataless -print \
  | tr '\n' '\0' | xargs -0 -P8 cat > /dev/null
```

### Prefer the local binary over npx

`npx next build` sat at 0% CPU with no worker at all, while `./node_modules/.bin/next build`
ran normally from the same shell. Use the local binary for anything long-running.

## 6. House rules for the code itself

### `src/lib` is pure

No `@/` imports. Relative imports carry **no** `.js` extension. No `window`, no DOM, no React,
no zustand. No `Date.now()`, `Math.random()`, or `performance.now()` — those are injected by the
caller so tests are deterministic.

### Adding a pure module

`tsconfig.test.json` has `rootDir: "src/lib"`, no `paths`, `module: nodenext`, no DOM lib. Tests
import from `../.test-build/<name>.js`. **A new module must be added to the `include` array
explicitly** or its tests will not compile.

`set-state-in-effect`, `refs` (no `ref.current` during render), `preserve-manual-memoization`,
`purity`, `static-components`. The ESLint baseline is **zero errors**. Currently there is one

## 10. AI System Updates — the rules that keep it safe

`src/lib/sysupdate.ts` is a trust boundary: a model's reply reaches the OS through it and
nothing else. Three rules, and they are not negotiable.

1. **Nothing is believed.** Every proposed theme is re-validated against the same contrast
   gates the fifty built-ins pass, and one that fails is DISCARDED, not applied with a
   warning — an unreadable OS cannot be used to fix itself. Colours must be hex: a colour
   that cannot be measured cannot be gated, which is why `rgb()` and `color-mix()` are
   refused everywhere except `--border`.
2. **Only `TUNABLE` can be written.** Twenty keys. Keys, provider/model selection, the dock
   app list and the vault are deliberately absent so no proposal can lock the user out. If
   you add a key, ask first whether a hostile value for it could make the OS unusable.
3. **Every apply is reversible.** `planApply` records the previous value of everything it
   touches; `planRevert` replays it. A value the user has changed BY HAND since the update is
   left alone and reported as skipped — an undo must not undo someone else's later decision.

Two traps met while building it, both worth not repeating:

- `Number(null)`, `Number("")` and `Number(true)` are all finite, so a bare `Number()` cast
  turned `"glass": null` into zero blur. Absence has to stay absence.
- A widget's `customId` is a TOP-LEVEL field on a widget item, not inside `config`. Reading it
  from `config` removed the widget from the store and left the dead tile on the desktop.

The JSON object is extracted by counting braces, not by matching a fence, because widget
markup contains braces; a truncated reply returns null rather than half an object.

## 11. Accessibility — what is now honoured, and what to preserve

- `prefers-reduced-motion` drives the same declarations the in-app toggle does. It used to
  set `--motion: 0` and stop, which nothing read — the toggle was the only thing that worked.
- `prefers-reduced-transparency` drops the glass blur for a solid panel.
- `prefers-contrast: more` does the same and takes borders to `currentColor`.
- `npm run check` fails an icon-only `<button>` with no `aria-label`.

If you add a media query, verify it in the BUILT stylesheet, not the source: dev does not

## 12. Context menus — one listener, and why it is in the capture phase

`src/shell/useGlobalContextMenu.ts` is the ONLY `contextmenu` handler in the shell. It is
installed on `document` in the **capture** phase deliberately: a handler anywhere in the tree
that calls `stopPropagation` would otherwise stop the event reaching it and the browser's own
menu would win. Do not add a second handler — contribute a section instead.

The bug it replaced is worth remembering as a class: Desktop's handler returned early for
anything inside `[role=dialog]` **before** calling `preventDefault`, and every window carries
`role="dialog"`. A guard placed before the side effect it is meant to protect disables the
side effect everywhere the guard matches.

- **To add items to a menu**: `registerContextTarget(el, builder)` from `@/kernel/ctxmenu`.
  Builders are collected from the event target upward, nearest first. Re-register when the
  builder's inputs change — it is a `WeakMap.set`, it costs nothing, and it avoids a ref
  (mutating a ref during render is an ESLint error here).
- **To use the right button for something else** (Minesweeper flags a square): put
  `data-ctx-skip` on the surface. The browser menu is still suppressed; ours just stays away.
- **Placement flips, it does not clamp.** A clamped menu sits under the pointer that opened
  it and the button release activates an item. `placeMenu` is tested for this.
- Keyboard follows the ARIA menu pattern, including Shift+F10 and the Menu key.

## 13. Context folding — the harness after step 40

`src/lib/harness/fold.ts`. Past `foldAfterSteps` (8) the older steps fold into a counted
ledger, curated incrementally by deterministic rules. It is a CURATOR, not a summariser: no
model is asked what mattered, because a model asked that every step is both the cost and the
"context collapse" the module exists to avoid.

Two things to preserve:

- **Only the prompt is folded.** `run.transcript` stays complete — it is the receipt — and the
  ledger points at it by path so the agent can read the detail back.
- **Digits normalize together** in the dedupe key, so "timed out after 3000ms" and "after
  5000ms" are one recurring failure with a count, not two singletons. That count is the most
  useful thing you can tell a model that is looping. It also means fixtures that differ only
  by number collapse — which surprised a test of mine before it surprised anyone else.

## 14. MCP — speak what the server answers with

`src/lib/mcp-wire.ts` holds version negotiation, request shape and list caching, and is pure.

We advertise `2026-07-28` and then speak whatever `initialize` answers with. Most servers are
still on `2025-06-18`, and a client that only speaks the newest talks to nothing. On a
stateless server, `_meta` carries the protocol version and client identity on every request
and `Mcp-Method` / `Mcp-Name` carry routing; on an older one neither is sent, byte for byte as
before. A session id a server issued is echoed on every revision — sessions left the protocol,
not the servers.

`tools/list` is cached per server **and** per negotiated version. The same server can answer
differently under each, and serving one for the other is a silent, very confusing bug.

## 15. Patterns — what keeps going wrong

`src/lib/harness/patterns.ts`, surfaced on the Harness app's Patterns tab.

Only recurrent patterns are reported, and each carries the run ids it came from. A flag
repeated inside one run counts once, so a chatty run cannot manufacture a trend. Cost outliers
are measured against the median, not the mean: against a mean, two runaway runs drag the
average up far enough to hide themselves.

A failed-verdict pattern hands its objective over but does **not** create an `EvalTask`. That
type requires a definition of done and a mandatory negative control; a machine-written
anti-control that nothing could fail would turn the golden set into "the guard still fires",
which a guard that fires on everything also satisfies. A person writes that part.

## 16. Live jobs, AIOS Chat, and phone/desktop switching (2026-09-23)

**Gates at the end of the session:** `npm run check` OK · `npm test` **879/879** · `tsc` clean ·
ESLint 0/0 · `next build` compiles. Not committed or pushed when this was written.

- **Live jobs — `src/kernel/jobs.ts`.** A non-persisted store of work in flight. Each job has a
  status (running/blocked/done/error/timeout), optional `progress` 0..1 (undefined draws a spinner,
  never a fake bar), a `target` {appId, args?, windowId?} and `actions` (Approve/Deny/Redo).
  `goTo(target)` focuses the exact window or opens the app, and emits `shell:show-app` so the phone
  shell leaves its home screen. It is exposed as `__aios.stores.jobs`.
- **Where jobs come from.** Every model call is mirrored from the existing `span` bus event
  (`installJobRecorder` in `src/shell/LiveToasts.tsx`), targeted at the window focused when it
  started. Callers that track themselves are skipped via `SELF_TRACKED` (AIOS Chat). Slow app
  loads (>250ms) come from `AppSkeleton` in `registry.tsx`. Trigger-fired harness runs come from
  `lib/harness-triggers.ts` and lead to the Harness.
- **Notifications are clickable.** `Notification` gained `target` and `jobId` (serializable,
  because they persist). The `notify` bus event forwards both. The bell menu shows an Activity
  section, and the bell turns into a spinner while anything runs. Toasts: bottom-right on desktop,
  top on phones (`<LiveToasts compact/>`).
- **AIOS Chat — `src/shell/AiosChat.tsx` + pure `src/lib/aios-agent.ts`.** It sits in the top bar
  between Search and the model picker, and on the phone home screen. A JSON tool protocol, 8 steps
  max. Tools that change things (write_file, create_app, send_email, create_calendar_event,
  close_window) block the job with Approve/Deny and send a notification. After 60s with no answer
  the job times out with a Redo button, and Redo consumes the old job. Email is only ever a
  draft plus a mailto link. Calendar writes `.ics` into `/Calendar` (RRULE for routines).
- **Phone <-> desktop — `src/lib/shell-mode.ts` (pure, tested).** The `phoneMode` setting is
  auto|desktop|phone. In auto, a touch phone on its side gets the full desktop. There is a one-time
  notice (`phoneTipSeen`), a "Full desktop" button on the phone home screen, a "Phone view" button
  on the forced desktop (placed clear of the dock), and a "Phone & Screen" tab in Settings.
  `MobileShell` now renders `ContextMenuHost` (backlog item 1) and switches to the app view on
  `app:open` and `shell:show-app`.
- **MCP Hub overlap on phones (bug class for §7).** `.app-sidebar` in the narrow container rule
  had a `max-height` and no `overflow`, so a long list painted over the pane stacked beneath it.
  The fix is `overflow-y: auto` in `globals.css`, which covers every app using `.app-sidebar`.
  Hit-testing (`elementFromPoint`) does NOT detect this bug, because the later sibling wins the
  hit. Verify it with a screenshot.

## 17. A loop that always delivers, judges that are not the builder, System One, and a desktop that travels (2026-09-23, second session)
