## The finding that matters most

**REST Countries is dead, and the test suite could not have told you.**

`countries` was in the original 25 services. Its parser test passed, because it was written
against a payload recorded when the API worked. A live probe found that `v3.1` — and the
`v5` its own deprecation notice tells you to migrate to — both now answer with:

```json
{"success": false, "data": null,
 "errors": [{"message": "This API version has been deprecated..."}]}
```

A recorded-payload test is structurally incapable of catching this. It proves a parser
handles a shape; it cannot prove anyone still sends that shape. The only check that finds
it is calling the thing.

So all 42 services were then probed live through the MCP route. **40 answered with real
data on the first pass.** Of the other two:

- `countries` was genuinely dead. It now points at the World Bank, which is keyless,
  public-domain and confirmed live — with a narrower fact set (capital, region, income
  group, coordinates; no population, languages or currencies), and the code says so.
- `wayback` returned `{"archived_snapshots": {}}`, which honestly means no snapshot for
  that query. Not a bug; the parser reported it correctly.

`dictionary` failed the first sweep with HTTP 522 and passed the second. Its error message
said *"This is a transport failure, not an empty result"* — which was exactly right, and is
why that distinction was built in the first place.

**42 of 42 are now confirmed answering live.**

## What was built

### 1. Seventeen more free services — 25 to 42

Every one was probed live BEFORE its parser was written, and every `reach: "direct"` was
set by reading the host's real `access-control-allow-origin` header rather than guessed.

Science: OpenAlex, openFDA drug labels, GBIF species.
Developer: Stack Overflow, PyPI, crates.io, deps.dev, NVD vulnerabilities, Docker Hub.
Knowledge: On This Day, Wikipedia article traffic.
Earth: reverse geocoding, historical weather.
Money: exchange-rate history.
Civic: Federal Register, postal codes.
Media: Wikimedia Commons.

One design decision worth recording: **OSV.dev was dropped in favour of deps.dev.** OSV's
package search is POST-only, and supporting it would have meant teaching `/api/proxy` to
relay POST bodies — turning an SSRF-guarded GET relay into something that can POST
arbitrary bodies to arbitrary hosts. deps.dev answers the same question over GET. Not
widening a security boundary for one data source.

### 2. The live services over MCP

`/api/harness/mcp` now serves all 42 alongside the deterministic tools — 51 in total. Any
MCP client that connects gets keyless access to every one.

On by default, and the reasoning is in the route rather than assumed: this deployment
already ships `/api/proxy`, which relays *any* public URL for an unauthenticated caller, so
a fixed catalogue of read-only GETs against named hosts is strictly less exposure. The one
real cost is attribution — requests leave from the deployment's IP, so a stranger hammering
the route spends *your* rate limit at GitHub or NVD. `WEBAIOS_MCP_LIVE=off` turns it off.

**The bug this introduced, and how it was caught.** The first version passed
`redirect: "error"`, and `restcountries.com` answers 301 to a different host — so that tool
failed permanently with a bare "fetch failed" while the browser path, which goes through
`/api/proxy` and has followed redirects all along, worked fine. Unit tests could not see it:
the transport is injected there, which is what makes the module testable and also what
makes this class of bug invisible to it. Found by calling all 42 through the real route.

The fix follows redirects and re-resolves each hop against the same SSRF rule `/api/proxy`
uses — judging the *address*, not the hostname, because a name resolves wherever its owner
likes. Following blindly would have let a hostile upstream redirect this function into the
deployment's own cloud metadata.

### 3. MCP resources and prompts, replacing two empty stubs

`resources/list` and `prompts/list` used to return `[]`. Now:

- **Resources** are the fixture corpus, one per document, at `webaios://docs/<id>`. A
  resource returns the WHOLE document, unlike `read_doc`, which deliberately returns a
  five-sentence window — that budget exists to create reasoning pressure inside a ReAct
  loop, and a client reading a resource directly is not in one.
- **Prompts** are the worked ReAct exemplars, with a `density` argument. A test asserts the
  refusal example survives into the output: a model shown only successes learns to produce
  the shape of a success.

Capabilities are advertised only when a corpus was actually supplied, because advertising
one this server does not serve makes a conforming client call it and get a
method-not-found it had every right not to expect.

### 4. MCP Hub — a new app

MCP had no surface of its own. The client lived in a panel inside AI Studio, seeded with
four localhost editor URLs, which is enough to reach a server you already knew about and
nothing at all if you did not.

The Hub is a directory of twelve servers — this deployment's own, six local (Godot, Unity,
Unreal, Blender, filesystem, git, memory), and four public (GitHub, DeepWiki, Context7,
Hugging Face) — plus connect, the tool list a server actually returns, and a form that
calls one.

The load-bearing part is the routing hint. A localhost server is reached **from the
browser**, because over there `localhost` is your machine; the relay's loopback is the
deployment's, which `/api/mcp` refuses by design. A public server is the opposite: almost
none set CORS for a browser origin, so it must be relayed. Backwards in either direction
gives a network error with nothing in it. `shouldRelay` is the single rule, and a test
asserts every directory entry's declared value agrees with it.

**Verified live:** the MCP client in this repo connected to the MCP server in this repo and
got **51 tools**; `kpi` returned the audited figure with its formula in 8 ms, and
`web_federalregister` returned real documents published two days earlier.

### 5. The golden set finally has a caller

`runSuite`, `diffAgainstBaseline`, `suiteToMarkdown` and fifteen seed tasks with mandatory
anti-cases have been complete and tested for sessions, and nothing in the app called any of
them. A suite nobody runs is the same as no suite, except that it looks like coverage.

Two things the binding is careful about, both from `ask()` rather than from the evals
module: spend is checked before **every** dispatch, because `ask()`'s own budget stop
throws and a suite that checked once would discover the ceiling by losing a run's trace
mid-flight; and concurrency defaults to **one**, because a golden set is N tasks times
(main + anti + repeats) model calls and fanning that out is how verification becomes the
most expensive thing the OS has ever done.

Eval runs pass `webServices: []`. A task whose answer depends on today's exchange rate
cannot be a regression test.

The panel leads with rejected tasks rather than results, because a task refused at
registration covers nothing and a pass count cannot show you that.

**Verified live with no API key:** 15 tasks ran, 0 passed, 15 failed, each with its unmet
criteria quoted — `"kpi called 0x (need >= 1)"`. Pinning a baseline from that red suite was
**refused**: *"A baseline taken from a failing run makes those failures the expected state,
and the next comparison will call them unchanged."* No baseline file was written. The
report was persisted to `/harness/evals/`.

## What was NOT verified

- **Still no live model call.** Unchanged, and still the largest gap. Every harness, swarm
  and eval run in both sessions ended without a model answering. That is why the golden set
  is 0/15: the runner works, the tasks are valid, and nothing was there to answer them.
- **The MCP Hub was only driven against this deployment's own server.** The twelve-entry
  directory is tested for internal consistency and the routing rule is tested both ways,
  but no Godot, Unity, Blender, GitHub, DeepWiki, Context7 or Hugging Face server has
  answered this client. The four local ones need software running that is not installed
  here; the four public ones were not contacted.
- **No MCP client other than this repo's has connected to `/api/harness/mcp`.** Claude
  Desktop, an IDE and every other real client remain untested against it. The handshake,
  tool list, tool call, refusals, notifications, resources and prompts were each exercised
  over real HTTP by curl and by this repo's own client.
- **The redirect-following fetch in the MCP route has no unit test.** It needs DNS and a
  live redirect, and the route file cannot be compiled by `tsconfig.test.json`. It is
  verified only by the live sweep — which is what found the bug it fixes, so the coverage is
  real but it is not a regression guard.
- **Rate limits were not exercised.** NVD allows roughly 5 requests per 30 seconds
  unauthenticated and GitHub's unauthenticated search is 10 per minute. The sweep ran each
  service once. Behaviour under sustained use is unknown.
- **`reach` is still unverified for the six proxy-only services from a browser.** They work
  through the relay, which is how they are configured; nobody checked whether any of them
  would also work directly, so one or more may be routed through the proxy unnecessarily.
- **Nothing was deployed.** `next build` passes locally with `/api/harness/mcp` in the route
  table; no push, no Vercel build.
