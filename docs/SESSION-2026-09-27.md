## 1. iPhone / PWA fit
- Cause (sources read): iOS 26 installed web apps with black-translucent +
  viewport-fit=cover report the viewport short by the top safe-area inset, so a
  band that tall is left at the bottom. WebKit bug 301108, still NEW. One team that
  measured on device found no CSS recovers it (paint capped); two others shipped
  100lvh / 100dvh without device confirmation.
- Fix, layered: .os-root is position:fixed; in an installed app it uses 100lvh, or
  --os-fill-h (measured screen height) when lib/viewport-fit.ts sees the exact
  signature (gap == top inset, translucent bar, iOS). wm.workArea and useViewport
  use kernel/viewport.ts appHeight() so maximized windows follow. Settings > Phone &
  Screen: Full-bleed / Solid status bar + a live readout of the numbers.
- Trap: Next's appleWebApp always emits a status-bar-style tag; and a JSX meta that
  the boot script edits is re-created by React 19 hydration (two conflicting tags
  seen). The boot script now creates the tag itself.

  with the fill var, lvh otherwise. Overflow audit of all 38 apps at 402x874 and
  375x667 in phone view: 0 cut-off controls/text (detector proven by a planted
